# 生图工作台剩余功能商业化优化方案

## 目标

在现有 React/Express/MySQL/Redis/BullMQ/Socket.IO/私有 OSS 核心上，完整迁移第 28 轮工具的主要用户能力。浏览器仅作为编辑界面和短期上传通道；项目、步骤资料、素材档案、任务、输出版本、排版稿、导入导出记录全部由服务端持久化。保留现有 API 凭证配置入口，不在新模块复制或向浏览器暴露密钥。

本方案把当前版本定位为“核心底座与快速创作首批”，不把现有工作台页面视为原工具的完整替代品。未完成下表中的关键能力前，不通过完整迁移验收。

## 目标产品流程

1. **快速创作**：新建会话 → 输入/润色/读图提示词 → 选模型参数与参考素材 → 提交后台批次 → Socket 实时通知 → 选择、锁定、重做和下载结果。
2. **商品项目**：新建商品 → 分类上传素材 → 自动识别并人工校正商品信息/素材档案 → 五维创作方向逐项确认 → 定视觉风格和平台规格 → 配产品/型号 → 生成并审核分镜 → 逐页生成提示词 → 试打样确认 → Redis 批量生产 → 复核/叠字 → 自查并生成导出包。
3. **项目复用与恢复**：选择可复用的品牌偏好 → 新商品事实保持独立 → 导入旧工程或从浏览器 IndexedDB 迁移 → 服务端确认 OSS 文件与记录完整后结束迁移。

## 当前实现进度

本轮已落地五维创作方向表与候选表、逐维 Redis AI 候选任务、采纳/拒绝/手工编辑和乐观版本控制；既有商品分析结果会进入同一候选池。素材识别结果写入独立档案表，人工校订与 AI 结果分层且互不覆盖。快速生图增加模型档案驱动的尺寸/质量选择、最多 4 张的批次和商品参考图选择；竞品素材只可供版式分析，服务端会拒绝将竞品图作为生成参考。

这仍是分阶段迁移。视觉风格与平台规格、商品/型号主档、分镜逐页审核、提示词版本、试打样/暂停/锁定、排版、导入导出、品牌复用及用量账本仍未完成，不能作为完整迁移验收。

## 数据与接口优化

### 数据表

保留当前 `projects/assets/jobs/generations/job_events/outbox/model_profiles/audit_logs` 基础表，新增或拆分以下业务表，避免将所有状态塞入不可检索的大 JSON：

- `product_profiles`、`product_variants`：商品身份、事实字段、来源与型号/颜色变体。
- `creative_dimensions`、`creative_candidates`：五维候选、手写项、采纳/拒绝状态、来源任务与版本。
- `asset_annotations`、`asset_relations`：逐图档案、置信度、人工覆盖、型号/颜色及用途关系。
- `brand_profiles`、`brand_profile_versions`：跨项目可复用的品牌资料、客户偏好和叠字规则。
- `storyboards`、`storyboard_shots`、`shot_references`：分镜、审核状态、产品/素材引用、版式理由、版本快照。
- `prompt_versions`：每页指令、来源指纹、模型/模板版本、人工编辑与过期状态。
- `generation_batches`、`generation_slots` 或扩展现有 generation：试打样阶段、暂停状态、并发/限流轨迹、每张图片的审核/锁定状态。
- `typeset_documents`、`typeset_layers`：排版稿及可重复渲染参数。
- `exports`、`project_imports`：异步导出、下载状态、旧项目导入和核对结果。
- `usage_ledger`：按用户/组织、模型、任务、输入输出 token/图片数记录可核算用量；不能只依赖估算字段。

JSON 适合保留模型原始结构化结果和可扩展设置，但正式字段、筛选条件、计费单位、关联关系要规范化并加索引。所有表须包含租户/所有者、时间戳和逻辑删除策略；对象访问始终以 owner/organization/project 关系为边界。

### API 契约

为项目/品牌、商品/变体、候选项、素材档案、分镜/页面、指令版本、批次/槽位、排版稿、导入/导出和用量分别定义版本化 REST 契约及错误码。每个写操作使用幂等键和乐观版本；任务 API 返回 `202 + jobId`；列表使用游标分页。生产阶段补齐 OpenAPI、限流规则和契约变更记录。

Socket 只发任务 ID、项目 ID、事件序号、状态和安全摘要，不发图片字节、密钥或完整上游响应。任务状态和事件以 MySQL 为准；客户端只在首次加载、Socket 重连、用户主动刷新时读取快照/事件游标，不做定时轮询。

## Redis 任务设计

- 将任务明确拆分为 `analysis`、`text`、`generation`、`typeset`、`export` 队列；确保每类任务有对应 Worker、并发、超时、重试和隔离配置。当前定义但尚未消费的队列不得被误报为已支持。
- 延续 MySQL transactional outbox；事件投递至少一次、业务处理幂等。每页每个输出槽位独立持久化；重试先恢复已有 OSS 对象/上游任务，避免重复生成和重复扣费。
- Redis 中保存可恢复的批次控制信息，暂停/继续是服务端命令；关闭浏览器不影响执行。为单用户、组织和模型设并发/速率预算；上游 429 采用共享令牌桶和动态退避，不能只降低单进程并发。
- 定义 queued/running/retrying/paused/partial/completed/failed/cancelling/cancelled 状态机和合法转移；所有终态写事件、错误码和时间。加入 stalled job 恢复、死信处理、队列积压告警和 Worker graceful shutdown。
- 导出和叠字需要相同的后台保障；ZIP、大图和排版不能在 HTTP 请求线程或浏览器长时间执行。

## 安全、存储与迁移

- 上传接口实施项目授权、数量/字节配额、MIME+魔数+解码校验、可选恶意文件扫描、SHA-256 去重和断点/失败重传。客户端直传仅使用短期、限定 object key/content type/大小的凭证。
- OSS 全部私有；图片展示使用短期授权；输出 ZIP 设置独立保留时限。数据库只存 object key、校验值和元数据，禁止永久 URL/Base64。
- 由管理员配置 provider 域名白名单、HTTPS 和 DNS/IP SSRF 检查；禁止重定向到非信任地址。外部模型错误先归一化，再脱敏入库。
- 迁移程序按项目分批执行：读取本地 IndexedDB 或旧工程备份 → 上传图片到私有 OSS → 转换旧 ID/分类/分镜/选择状态 → 写服务端记录 → 校验记录数、字节数和摘要 → 输出差异报告。迁移支持断点续传，不在校验完成前删除旧本地数据。
- 删除项目采用可审计软删除；后台清理任务在保留期后清理 MySQL 关联记录和 OSS 对象，并提供管理员恢复窗口及组织级保留策略。

## 分阶段交付与验收

### A. 需求契约和数据迁移

- 对两份 HTML 的差异、更新说明、步骤状态、工程导入导出结构做字段级盘点；保留可追溯映射表。
- 产出 OpenAPI、状态机、数据字典、配额/保留策略、迁移工具格式和回滚方案。
- 用真实第 28 轮工程包做无损往返样例，所有素材、选项、分镜和版本计数一致。

### B. 项目与素材工作流

- 交付商品/变体、四类素材、五维候选、逐张档案、品牌资料、风格/规格/产品主体和手动校订。
- 素材分析分批进入 Redis，可失败重试；局部失败不会覆盖已人工确认数据；再次分析显示差异并由用户采纳。
- 旧项目导入可预览映射和容量，失败项可重试；OSS 对象、数据库行和校验摘要三方对账。

### C. 分镜、指令和可控批次

- 分镜逐页编辑、人工审核、商品变体/商品图/竞品版式映射和理由；输入变化能精确标记受影响指令过期，不误删人工修改。
- 快速创作与商品项目共享 provider adapter，但保留独立会话历史/参数档案。
- 支持试打样、批次暂停继续、单页重出、只重试失败槽位、锁定已选结果、动态限流；每槽位在重启/重复消息/网络中断下不丢失且不产生意外重复计费。

### D. 叠字与导出

- 叠字预览和服务端成品渲染像素级一致；保存字体、位置、行距、颜色、模板和底图关系；移动端触控编辑可用。
- 自查报告列出缺图、未审核、画面文字风险、无效素材引用和失败页面；用户确认后才可导出。
- ZIP 由 Redis 导出 Worker 生成并落私有 OSS；包含成品、原底图、清单/授权信息及可导入工程备份；下载链接短期有效，导出记录可查询。

### E. 运营、上线与质量门槛

- 组织/用户隔离、模型可用性、日/月配额、成本账本、管理员审计检索、告警和保留清理任务。
- 自动化验证覆盖纯逻辑、真实浏览器启动/主要按钮、移动视口、数据库迁移、Redis Worker 重启、重复 Outbox、OSS 故障、上游限流/超时/SSRF、Socket 重连和旧工程往返。
- 生产验收完成负载/故障演练、备份恢复、迁移回滚、浏览器矩阵、运营手册和发布灰度。只有全部关键验收通过才标记“完整迁移”。

## 发布门槛

1. 浏览器刷新、关闭或断网后，项目、结果和任务都可从服务端恢复；所有耗时操作由 Redis Worker 执行。
2. 输入/生成/叠字/导出图片都落到私有 OSS，任一越权对象请求返回拒绝；删除与恢复行为可审计。
3. 第 28 轮主要功能均有对应业务数据、可追溯状态、失败恢复路径和验收用例。
4. 旧项目至少支持一种正式迁移路径且有往返校验，不要求用户手工重做商品资料。
5. 配额、用量、成本、错误率、队列等待时间和导出成功率可供运营查看；没有“页面显示成功但数据库/OSS 未保存”的状态。
6. 未配置 MySQL/Redis/OSS/模型档案时明确提示不可用原因；无本地存储或内存队列假成功降级。
