# 接单申请与品牌方确认

## 业务规则

- 设计师申请或回应邀请时，只创建接单申请。品牌方同意后才创建正式设计任务。
- 每个订单与设计师最多保留一条申请；撤回或关闭后可重新申请，报价版本递增。
- 待审申请可修改报价与说明，或撤回。品牌方拒绝后，本期不能再次申请。
- 每个订单只能批准一位设计师；其他待审申请关闭，未回应的邀请取消。
- 已接单的历史订单保持原任务。新增审批逻辑适用于后续申请。
- 设计师必须有公开且完整的主页和审核通过的公开作品，未暂停接单，且未达到在途订单上限。申请和批准时均核验。
- 申请无需选择代表作品。品牌方申请卡片自动展示设计师当前公开作品的前三件，可预览图片、打开公开主页与完整作品集；旧申请绑定的作品不再影响展示与审批。
- 订单取消时关闭待审申请；已下架或超过截止时间的订单，在读取申请时同步关闭，审批接口始终禁止处理失效订单。
- 未提交或待修改的任务可退回；恢复原预算，取消待结算收入，关闭该次已批准申请。已支付尾款的任务不能退回。

## 金额

加价为非负金额，最多两位小数；加价大于零时必须填写原因。

最终总价 = 原预算 + 批准的加价；尾款 = 最终总价 - 实际已付定金。
已支付定金保持原金额；平台服务费沿用现有规则，按尾款乘服务费率计算。

例如原预算 ¥1,000、已付定金 ¥300，加价 ¥200，服务费率 15%：

| 项目 | 金额 |
| --- | ---: |
| 最终总价 | ¥1,200 |
| 已付定金 | ¥300 |
| 尾款 | ¥900 |
| 平台服务费 | ¥135 |
| 设计师所得 | ¥1,065 |

批准后生成待结算收入；尾款支付确认后结算。重复支付通知不会重复计入收入。

## 页面入口

| 系统 | PC | 移动端 |
| --- | --- | --- |
| 设计师 | 接单大厅、邀请订单、我的接单申请 | 订单详情、邀请订单、我的接单申请 |
| 品牌方 | 我的订单中的接单申请抽屉 | 订单详情 → 接单申请列表 → 申请详情 |
| 作品资料 | `/designers/:id` | `/mobile/designers/:id` |

使用既有 Modal、按钮、输入框、卡片及品牌方/设计师主题变量。
通知沿用现有站内消息与 SSE，实现申请、报价、处理结果的刷新及对应端的深层链接。

## API（统一 `/api` 前缀）

| 方法 | 路径 | 权限/用途 |
| --- | --- | --- |
| POST | `/design-orders/:orderId/applications` | 设计师提交申请 |
| GET | `/design-orders/:orderId/applications` | 订单发布者或同组织品牌方管理员查看 |
| GET | `/order-applications/mine` | 设计师查看自己的申请 |
| PATCH | `/order-applications/:id` | 申请人修改待审报价 |
| POST | `/order-applications/:id/withdraw` | 申请人撤回 |
| POST | `/order-applications/:id/approve` | 品牌方批准 |
| POST | `/order-applications/:id/reject` | 品牌方拒绝，`comment` 必填 |

提交/修改字段：`extraAmount`、`message`；修改及审批必须提交最新 `version`。
旧 `/design-orders/:id/claim` 接口转为提交申请，返回申请，不再直接创建设计任务。
邀请的 `respond` 接口接受同样报价字段，`action: accept` 也只提交申请。

审批锁定订单、申请与设计师，在同一 MySQL 事务内写入任务、订单金额、申请状态及待结算收入。
同意操作重复请求返回已有任务；过期报价版本返回 409，界面提示重新加载。

## 数据库与部署

新增 `order_applications` 表，以及订单的 `original_budget`、`accepted_application_id`、`agreed_extra_amount` 字段。
迁移只增加结构并补齐历史原预算，不自动生成历史申请或更改历史任务。
历史 `portfolio_ids` 列保留以兼容已部署数据库，后续提交/修改写入空数组；无需额外迁移。

```powershell
pnpm migrate:order-applications
pnpm build:server
pnpm build:web
```

本地回归脚本：`pnpm check:order-applications`。
加 `-- --http` 可检查运行中的本地 API 权限与兼容入口。
脚本使用唯一临时数据并在结束时清理，关闭企业微信推送；支付结算使用模拟状态，不发起真实支付。
覆盖报价校验、越权、版本冲突、并发批准、重复批准、取消/撤回/拒绝、邀请申请、金额持久化、收入幂等与退回任务。

SSE 沿用当前单进程实现；部署多个后端实例时，跨实例广播需要另行接入共享事件通道。
