# 订单协作聊天：移动端交互方案

这是桌面端 [订单协作沟通设计](order-chat-interaction.md) 的移动端版本。设计图：[PNG](mobile-order-chat-flow.png) · [可编辑 SVG](mobile-order-chat-flow.svg)。示例品牌、订单和消息仅用于表达交互。

## 四屏流程

| 页面 | 进入与操作 | 返回行为 |
| --- | --- | --- |
| 1. 协作会话 | 从订单详情或协作入口进入；按「全部 / 待我处理 / 进行中」筛选，以订单为单位展示最新动作、未处理数和卡片状态。 | 返回原来的订单或任务位置。 |
| 2. 订单聊天 | 顶部保留订单名、阶段与「档案」入口；消息、需求卡、批注按时间顺序显示。底部输入区和工具入口固定在安全区上方。 | 返回会话列表时保留滚动位置与未发草稿。 |
| 3. 需求卡详情 | 点聊天中的卡片后全屏查看字段和素材。底部固定「提出修改 / 确认需求」；修改必须填写原因，确认需完成全部必填项校验。 | 回到原消息位置，状态变化追加一条时间线事件。 |
| 4. 协作档案 | 从聊天顶部进入，查看当前有效版本、确认人、时间、附件和来源消息；点击来源跳回聊天。 | 回到聊天时不重建会话。 |

## 关键交互约束

- **消息可靠性反馈**：文本先在本机持久化，随后显示「待服务器确认」；服务端落库后显示「已保存」。断线和刷新后保留待发内容并重试。未收到接收方回执前不显示「已读」。失败内容提供显式重试入口。
- **卡片版本**：品牌方提交 `v1` 后进入「待设计师确认」；设计师提出修改时保留原版本并生成后续版本。只有双方确认的版本进入协作档案的有效快照。
- **附件**：上传进度与发送状态分开；图片或文件上传完成并取得素材标识后，才能随卡片或消息提交。点素材全屏预览，图片批注从预览页进入。
- **底部操作**：键盘弹起时输入框贴在键盘上方；需求卡详情页的两个主动作始终位于底部安全区上方。长内容可滚动，操作按钮不遮挡最后一行。
- **导航**：设计师可在现有任务与接单入口之外增加「协作」入口；品牌方可在现有消息页增加「协作 / 站内通知」切换。订单会话与站内通知仍是两类数据。
- **小程序适配**：沿用相同的订单、卡片状态和历史消息接口；底部安全区、上传及 Socket.IO 连接采用小程序适配层。退到后台后重新进入时先补拉历史，再展示实时状态。

## 当前项目需要的后续工作

`/mobile/orders/[id]/chat` 已使用独立的全屏布局，聊天、档案、需求核对和 A/B 方案详情在移动端分屏显示，并避开 `MobileAppShell` 的全局页头与底栏。文字版卡片已接入消息保存；附件、图片批注、正式版本快照和微信小程序界面仍待开发。现有 `/mobile/messages` 是站内通知，不作为订单会话列表。
