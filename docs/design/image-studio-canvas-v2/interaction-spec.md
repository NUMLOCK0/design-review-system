# 生图工作台 V2：对话、动态任务与无限画布

状态：已按本方案开始实施；交互方案与页面实现同步维护。

## 1. 重构目标与现有基础

用户在同一项目中完成需求沟通、素材整理、风格探索、套图策划、图片生成、修改和交付。生成结果即时进入无限画布；执行步骤由所用 Skills、已有资料和任务目标共同决定。

当前仓库的基础：

- `workspace-flow.tsx` 定义了固定的 10 个阶段，适合商品套图，但不能表达不同设计任务的步骤差异。
- 业务 Skills 已有分类、说明、问题模板、完成标准和版本；需要扩展为包含输入、任务模板、产物和工具能力的工作配方。
- 无限画布已有图像、文本、分组、连线、选区与 Agent 面板能力，可作为新工作台的编辑与展示层。
- 商品项目和画布项目目前有独立持久化记录，需要建立同一业务项目下的关联。
- MySQL、OSS、后台 Worker、任务事件与模型配置继续作为运行基础。

实现进度（2026-10-27）：

- `/service/image-studio/[projectId]` 已切换为对话、无限画布、动态任务三栏工作台，手机端提供对话/画布/任务切换。
- 中央画布直接复用 `packages/infinite-canvas` 的项目画布页面和节点编辑能力；工作台通过稳定画布项目 ID 关联生图项目，不另造画布引擎。
- Agent 规划支持版本化动态任务图与 Skill 快照；任务状态保存在项目工作流 JSON，生成任务与结果继续使用既有后台 Job、OSS、Socket 和审稿记录。
- 商品图片可在工作台直接上传并关联到当前项目；生成结果以稳定槽位进入无限画布，保留用户已有布局。
- 仍需在运行环境完成数据库/OSS/模型配置后的端到端联调，并继续完善画布资产管理与各任务类型的具体业务动作。

## 2. 页面布局

桌面端按宽屏优先设计，主视觉为明亮、中性、卡片化，保留大面积画布。

| 区域 | 建议尺寸 | 内容与行为 |
| --- | --- | --- |
| 顶栏 | 高 56–60px | 返回项目、项目名、保存状态、版本、任务概况、分享/交付 |
| 工具窄栏 | 宽 52–56px | 项目、素材、画板目录、历史；按需打开，不常驻另一组宽侧栏 |
| 左侧 Agent | 默认宽 320px，可拖动至 420px | 对话、来源会话、Skills 标签、需求问题、计划摘要与快捷操作 |
| 中央画布 | 占剩余宽度 | 原图、参考图、方向、套图、版本、批注；支持缩放、平移和分组 |
| 右侧上下文面板 | 宽 288–320px，可收起 | 任务与属性两个页签；未选图片时显示任务，选择图片后可切到属性 |

1440px 下画布仍占主要区域；小于 1280px 默认收起右栏。面板开关保留在顶栏。画布全屏模式可同时收起两侧面板。

界面状态色：紫色为当前选择/主要动作，绿色为已完成/已确认，琥珀色为等待输入或复核，青色为参考资料，红色只表达失败。状态同时使用图标与文字。

## 3. 完整交互流程

### 3.1 创建项目与导入上下文

入口包括客服聊天中的“进入设计工作台”、工作台项目列表的新建按钮，以及已有画布的继续创作。

空项目画布中央显示简洁的起始卡：“这次想完成什么设计？”支持描述任务、上传素材、选择关联会话。举例“为这款随行杯做一套自然生活风格的天猫图片”。起始卡在任务成立后收起。

绑定会话时，在左栏展示会话名称、来源时间和已引用的表单/素材数量。Agent 整理需求简报，区分明确要求、建议、未填写问题和待核实商品信息。客服在简报卡上直接编辑关键项。

从当前会话选择图片时进入当前会话的图片库。上传或拖入画布后可标记商品原图、包装、版式参考或风格参考；分类会影响后续任务采用图片的方式。

### 3.2 推荐与组合 Skills

Agent 根据任务目标推荐工作 Skill，再匹配风格与渠道规则。例如：

- 工作 Skill：电商套图、品牌视觉提案、包装设计、图片审稿。
- 风格 Skill：自然生活、极简科技、年轻活力。
- 渠道规则：天猫、京东、小红书等实际交付约束。

用户看到中文名称、推荐原因和“将增加哪些工作”，可以添加、移除、替换，也可以在输入框中用 `@Skill` 指定。Skill 版本在本次任务中固定，后台修改模板不会改变执行中的项目。

已有业务 Skills 统一进入工作台的业务技能库。原画布本机 Agent 的扩展技能属于高级工具接入；普通客服使用已配置的服务端 Agent，无需填写本机地址或连接 Token。

### 3.3 动态生成任务计划

计划器读取任务目标、已确认信息、素材状态、Skills 工作配方与可用工具，生成带依赖关系的任务。步骤数量随任务变化，不预设固定六步或十步。

左栏输出一张计划摘要卡；右栏展开实际任务列表。每个任务显示名称、为什么需要、引用资料、预期产物、当前状态和可执行操作。

只询问无法从上下文得到的必要信息。缺少商品原图时，“生成图片”进入待补资料；调研、需求整理等独立任务仍可继续。问题直接在左栏卡片填写，也可以沿用聊天表单发给品牌方。

首次计划默认展示“开始执行”；若用户已经明确要求直接执行且提供了范围/数量，则在授权范围内继续。中途只在确有选择需要时停留，例如选风格、确认首张样图、确定交付版本。

### 3.4 自动执行与产物落到画布

后台按依赖调度任务；独立任务可以并行。用户离开页面后继续执行。

画布按产物组织命名画板，例如“商品资料”“调研与参考”“视觉方向”“天猫套图”“交付成品”。并非每个后台步骤都创建一个大节点：纯分析可以更新既有资料卡，图片生成必须对应可见图片槽位。

任务启动时就建立稳定槽位，显示“排队中/生成中”。结果保存成功后原位替换占位卡；失败保留位置并给出重试操作。实时结果进入原任务所属画板，不打乱用户已经摆放好的图片。

右侧点任务可定位相关画板；画布点图片可查看来源任务。任务状态以后台事件为准，画布布局单独保存。

### 3.5 风格探索与套图规划

风格探索任务可以产出 2–4 个候选方向，具体数量由 Skill 与用户目标决定。每个方向是一个可选择的画板，包含关键词、配色、参考图和可选试样。

选择方向后，可以点“使用此方向”，也可以在对话中说“保留 A 的配色，用 B 的构图”。Agent 创建组合方向并保留来源。

套图规划直接在画布中显示页面卡片：用途、尺寸、型号/颜色、短文案、画面意图与引用商品图。卡片可重排、编辑、删除或添加。张数是交付数量，与任务步骤数量分开显示。

未核实的参数、功效、售价不会自动进入成图文案。品牌方的新回答会更新对应资料，并提示受影响页面。

### 3.6 先出样、再批量生成

套图任务默认建议先试做一张代表性图片。用户可调整策略，明确要求整套生成时不重复询问同一授权。

首张图片直接出现在套图画板。用户可选择“沿用此风格生成其余图片”“调整后重试”或“更换方向”。批量运行时右栏显示具体数量，例如“图片生成 4/6”，与“任务完成 3/7”分开。

每张结果可单独选用、锁定、比较和再生成。任务出现部分失败时成功图片继续可用，“重试失败项”仅提交失败槽位。

### 3.7 在画布中修改图片

选中一张图，出现轻量浮动工具条：修改、生成变体、对比、设为成品。细节参数收进右侧属性面板。

左栏输入框展示当前引用的图片缩略图。例如用户说“让背景暖一点，杯子保持不变”，执行范围就是已选图片，并继承原图的商品与风格约束。

局部修改先在图上涂选区域；多选时输入框展示“已选择 3 张”，发送前可调整作用范围。修改生成新版本放在原图旁，原版本可随时返回。

### 3.8 审稿与交付

进入审稿模式后，画布仍可平移缩放，点击图片添加编号批注。批注包含图片版本、坐标、文字和处理状态。可选择一条或多条批注交给 Agent 修改。

客服内部确认与品牌方确认分别记录；品牌方的确认只能由对应身份操作产生。

交付通过选定/锁定的成品生成清单。对比版本、候选图、失败占位和调研参考默认不进入交付包。用户核对图种、数量、尺寸和文件名后导出图片或 ZIP，也可发回原会话供品牌方查看。

## 4. 不同 Skills 对步骤的影响

| 目标 | 可能产生的任务 | 主要画布产物 |
| --- | --- | --- |
| 电商套图 + 自然生活 + 天猫 | 商品核对、调研、视觉方向、套图规划、首张试样、其余生成、审核交付 | 商品资料、参考板、套图画板、成品画板 |
| 一张商品白底图 | 素材核对、背景处理、边缘检查、交付 | 原图与白底结果对比 |
| 品牌视觉提案 | 品牌简报、品牌研究、方向探索、视觉元素、应用展示、提案整理 | 多个方向画板与应用稿 |
| 图片审稿 | 收集审稿范围、逐图检查、标注问题、修改建议、版本复核 | 原稿、批注、修改版本 |

这些是样例计划，不是新的固定流程。没有多 SKU 就不创建型号分配任务；品牌规范已有且被用户采纳时复用相应产物；仅要一张图时不强加套图规划。

## 5. 计划变更与局部重跑

- 添加或更换 Skill 后先生成计划差异：新增任务、复用产物、受影响任务、预计新增生成数量。显示 V3 → V4，用户采用后执行新范围。
- 改配色影响方向、提示词和相关生成；素材核对与已有效的调研不重复执行。
- 改 SKU 只影响引用该 SKU 的页面；修改某张图的画面要求只影响该图片分支。
- 运行中的任务使用启动时的输入快照。其结果仍保留在原分支，并标注基于旧方案；不会覆盖新计划。
- 已锁定成品仍可查看；受上游修改影响时标注“需复核”，由用户决定是否创建新版本。
- Skill 条件不再适用的待执行任务可以标记跳过；已消耗工作的旧记录保留在历史里。
- 新资料只更新相关字段，不覆盖人工修改。重新分析先显示差异，用户可逐项采纳。

## 6. 画布交互规则

| 交互 | 行为 |
| --- | --- |
| 单击图像 | 选中图像，显示工具条和属性入口 |
| 双击图像 | 大图预览；Esc 返回画布 |
| 拖拽 | 移动所选图像/画板；拖入素材时上传并登记 |
| 空格拖拽 / 触控双指 | 平移画布；触控捏合缩放 |
| 多选 | Shift 点击或框选，可批量引用、排版、导出 |
| 引用到对话 | 输入区显示缩略图与引用数量，发送后固定引用版本 |
| 点任务 | 定位相关画板、强调该任务的图片，不移动其他内容 |
| 新结果在视口外 | 显示“新增 3 张 · 查看”，不抢走当前视口 |
| 删除画布节点 | 移除展示，可撤销；后台任务、源资产与其他引用不随之删除 |
| 暂停批次 | 停止继续派发未启动槽位；正在执行的槽位显示实际状态 |
| 比较版本 | 同尺寸并排/滑动对比，标明父版本与本次改动 |

默认隐藏依赖连线。需要追溯时可打开“查看来源”，只高亮当前选中图片相关关系，避免画布被工作流连线占满。

## 7. 动态任务与 Skill 配方

业务 Skill 在现有字段上扩展以下配置：

| 配置 | 作用 |
| --- | --- |
| inputSchema / questions | 必需资料、可选资料、稳定字段 key 和补充问题 |
| taskTemplates | 可规划任务模板及适用条件，允许省略不适用任务 |
| tools | 可使用的现有能力，如资料分析、网页搜索、图片搜索、图像生成、导出 |
| artifactTypes | 简报、研究卡、方向、图片计划、图像、批注、交付包 |
| reviewPolicy | 哪些节点需要选择/确认，哪些可自动继续 |
| completionCriteria | 任务是否产出有效内容的检查标准 |
| styleConstraints | 风格表达、商品保持项与避免项 |
| version | 本次任务采用的发布版本与快照 |

规划结果为带依赖的任务图。每项任务至少包含 `taskId、kind、title、skillId、skillVersion、dependsOn、inputRefs、outputTypes、reviewPolicy、status、planVersion`。自然语言说明用于规划，真正执行的动作必须对应已注册工具。

规划器可以按资料与目标组合步骤；执行器负责校验依赖和工具输入，并派发已满足条件的任务。一个业务任务可以拆成多个后台作业，例如 8 张图片生成对应 8 个槽位。

## 8. 状态与恢复

任务状态包括：待补资料、待确认、待执行、排队中、执行中、已完成、部分完成、失败、停止中、已停止、已跳过、待更新。

失败分为可重试、需补资料和配置不可用，右栏给出对应动作。图片未保存到 OSS 时不会显示为可交付成品。网络断开时显示连接状态；重连从服务端补齐任务事件并恢复槽位。

刷新后恢复项目、计划、会话、选择版本与画布布局；后台任务不会因为刷新重新创建。相同任务/槽位结果事件重复到达时只更新既有节点。

## 9. 数据与现有系统的连接

统一业务归属：一个 `image_studio_project` 关联一个主画布与若干创作分支。现有画布工程可绑定到项目，迁移保留原节点与布局。

正式数据分开保存：

- 项目与来源会话：项目、会话引用、已确认简报。
- 计划与执行：计划版本、Skill 版本快照、任务、任务输入、后台作业与槽位。
- 创作产物：artifact、版本/父版本、资产、来源任务、图片审核状态。
- 画布：node、frame、position、size、layoutVersion；节点引用 artifact，不以临时 URL 作为业务标识。
- 审稿与交付：批注、内部确认、品牌方确认、成品清单、导出记录。

图像仍统一保存 OSS，资产 ID 在画布与生图记录之间建立映射。签名 URL 是展示时取得的临时值。MySQL 保存业务和布局状态，Worker 执行任务，Socket 推送结果，前端将 artifact 状态投影为画布节点。

旧 Skills 迁移为默认工作配方，保留原问题模板、说明与完成标准；不直接把旧画布的本机扩展 Skill 当作业务技能记录。

## 10. 窄屏与手机

手机保留同一个项目与任务，采用“画布 / 对话 / 任务”三个底部页签。切换不重置画布视口。

属性、补充问题和任务详情使用底部抽屉，最高到安全区下方，内部滚动。审稿支持单指点标记、双指缩放平移；选中图片后底部提供修改与设为成品。批量任务在后台执行，手机也能继续查看结果。

## 11. 开发拆分与验收

1. 项目与画布归并：打通项目 ID、媒体资产映射和结果节点；生成图片可恢复地进入画布，用户布局不被覆盖。
2. Skills 动态计划：扩展配方、计划版本、任务执行与事件；不同 Skill 产生可解释的不同步骤，缺资料只阻塞有关任务。
3. 对话与画布协作：引用当前选图、局部修改、变体分支、方向选择和计划差异重排。
4. 审稿与交付：版本批注、身份区分的确认、成品清单和导出。

验收重点：单张白底图不出现整套商品流程；换风格只更新受影响任务；重连不出现重复图片；部分失败只重试失败槽位；调整节点位置不改变生成状态；旧计划结果不覆盖新版本；刷新能恢复；品牌方确认身份正确。
