# 生图工作台：电商平台图片要求调研与项目预设建议

调研日期：2026-10-15（Asia/Shanghai）  
范围：淘宝、天猫、京东、拼多多、抖音电商。  
本文件记录平台规格调研，以及依据调研完成的首轮工作台实现。当前实现覆盖规则选择、分用途生成配置与项目保存；尚未接入平台发布接口。

## 1. 结论与证据等级

新建项目应按“平台 / 业务渠道 + 商品类目 + 图片用途”加载规则。商品主图、长主图、白底素材、SKU 图、详情图和活动素材不能共用一个比例与张数限制。

下文使用以下等级，避免把工作台设计选择误写成平台限制：

- **官方正文**：本轮读取到官方页面正文，但仍须关注页面年代与适用范围。
- **官方索引**：搜索引擎提供官方页面的条文内容，直接打开页面为空或动态加载；上线强制校验前应在后台复核。
- **待核验**：本轮未取得足够的当前官方依据，数值不能作为平台强制限制。
- **工作台建议**：为制作效率提出的可编辑默认值，不代表平台要求或保证审核通过。

“检索日期”不是“规则生效日期”。旧公告、接口规格、国际业务规范不能自动扩展到当前全部商家和全部发布入口。

### 通用导出建议

- 默认 JPG（照片、场景），需要无损文字边缘时可选 PNG；对外发布是否支持其他格式须按平台核验。
- 使用 sRGB。网页图片优先检查像素和实际清晰度，不以 DPI 作为合格判据。
- 初期可设单张 JPG 目标体积不超过 1,000,000 字节，作为内部压缩目标；这是建议值，不是四个平台的统一限制。
- 若压缩损害文字或细节，优先拆分详情模块或调整排版，再结合真实上限导出，不为凑体积牺牲关键可读性。
- 生成母版与平台导出分离：按已接入模型能力选择足够的生成分辨率，再排版、裁切、缩放、压缩；记录真实母版像素，不能把插值放大描述为新增真实细节。
- 商品、Logo、标签、型号、参数来自用户提供的真实素材与资料；数值和精确文字优先独立排版。
- 多平台复用时分别排版，禁止通过非等比拉伸改变商品外形。

## 4. 新建项目的规则规划

### 4.1 建议输入

1. 平台：淘宝、天猫、京东、拼多多、抖音电商；现有“淘宝 / 天猫”可保留组名，但数据中允许区分渠道。
2. 店铺 / 经营渠道：如京东 POP、自营、国际，尚未选择时不应用某渠道专属规则。
3. 商品类目：尽量记录叶子类目；未知时使用通用建议模板并显示待核验项。
4. 图片用途：主图组、白底素材、SKU、详情页、长主图、活动素材，多选。
5. 规格摘要：逐用途显示尺寸、制作数量、体积目标，以及“官方规则 / 工作台建议 / 待核验”标签。

### 4.2 规则数据应分开保存

| 数据 | 示例 | 用途 |
| --- | --- | --- |
| 适用条件 | platform、channel、categoryId、placement | 避免用错平台或图片栏位 |
| 官方约束 | 比例、尺寸范围、允许格式、最大字节数、数量范围 | 有来源且范围匹配后才启用拦截 |
| 制作默认值 | 800×800、起始 5 张、压缩目标 | 可由用户修改，不标记为平台违规 |
| 内容条件 | 第几张展示什么、是否允许文字、是否须真实标签 | 用于分镜和验收 |
| 证据 | sourceUrl、sourceType、retrievedAt、effectiveAt、verificationStatus | 可追溯、处理旧规则和冲突 |
| 规则版本 | profileId、version、项目快照 | 后续规则变化不静默改动已有项目 |

规则冲突不能简单地“取最严格值”：先核对适用范围与有效期，只有官方明确的专属覆盖关系才能替换通用项；无法确定时提示复核。

### 4.3 校验与生成联动

- 已验证且适用的硬规则：导出不符时阻止该发布规格导出，并给出原因。
- 官方索引或冲突规则：给出核验提醒，不伪装成已完成全量验证。
- 工作台建议：只提醒，允许修改。
- 平台尚未验证的字段：保留空值，不能用猜测的上限补齐。
- 图片用途决定分镜：主图组不自动套用详情页的大字营销排版；标签和认证图优先使用原始资产。
- 切换平台 / 类目 / 用途后，保留原素材，重新计算输出规格与待审核项，不覆盖已确认内容。

## 5. 首轮实现状态

- 新建项目可选择平台、商品大类、店铺 / 经营渠道、细分类目和图片用途；所选预设与规则版本会保存在项目工作流中。
- 规格设置按主图、长主图、白底素材、SKU 和详情模块分别编辑画幅、目标画布、制作数量，并标出已核实规则、工作台建议和待核验项；每个平台显示本文件记录的参考来源。
- 分镜逐页指定交付用途；“按用途数量补齐页面”可按已选用途的制作数量建立最多 20 页待编辑分镜，不会自动提交生图任务。
- 生成任务按分镜用途选择模型支持的最接近画幅，并把目标像素和用途写入提示词及任务记录。生成服务实际返回尺寸仍由模型决定。
- 旧项目会读取已有工作流；没有用途规格的旧项目会加载平台默认预设，不要求数据库迁移。
- 尚未实现精确像素裁切 / 缩放 / 压缩导出，也没有按店铺渠道和叶子类目动态匹配平台硬约束。当前规格是可编辑制作配置，未核验规则不会阻止生成。
